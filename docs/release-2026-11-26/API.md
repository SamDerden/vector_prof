# Контракт API PM — кандидат

Все новые функции требуют миграций 001–013. JSON: UTF-8. Ошибки `{error: string}`; 400 JSON/параметры, 401 аккаунт, 403 владение/CSRF, 404 отсутствует или чужой ресурс, 422 схема, 429 ограничение + Retry-After, 502 AI, 503 функция не настроена. Не логировать cookie, вопросы, ответы или персональные поля.

## Мастерская

`POST /api/profession-assistant/message`. Cookies `vector_auth_session`, `vector_csrf`; заголовок `X-CSRF-Token` должен совпасть с cookie и записью сессии. Пользователь active + verified. Пример:

```json
{"profession_id":"prof_001","session_id":"<UUID принадлежащей аккаунту диагностики>","conversation_id":null,"request_id":"<новый UUID операции>","question":"А сколько учиться?"}
```

`profession_id` выбирается из GET /api/professions; пример не гарантирует наличие конкретного ID. Поля описания профессии/возраста от клиента не принимаются. `request_id` сохранять до ответа, повторять тот же ID при потере сети. При первом запросе ID диалога равен request_id: повтор с null не создаёт новую беседу. После ответа передавать conversation_id. При изменении вопроса использовать новый request_id. Один conversation_id нельзя использовать для другой профессии. Новая профессия — новый диалог.

Ответ:

```json
{"conversation_id":"<UUID>","status":"success","answer":"…","source_type":"internal","sources":[{"id":"prof_001","title":"Каталог Вектора: …"}]}
```

Статусы: success, out_of_domain, needs_clarification, insufficient_data. Источники — только серверные записи каталога; ссылки, сгенерированные моделью, отклоняются. Внешний поиск пока не подключён. Не отображать эту функцию как поиск по интернету.

`GET /api/profession-assistant/conversations` — последние 50 диалогов владельца. `?conversation_id=UUID` — последние 100 пар сообщений в хронологическом порядке. `DELETE` с тем же параметром и CSRF — удалить диалог, 204. Чужой UUID → 404. История не хранится в URL/localStorage.

Включение требует ASSISTANT_ENABLED=true и явно заданных ASSISTANT_DAILY_LIMIT (1–1000) / ASSISTANT_RETENTION_DAYS (1–365). Это технические диапазоны, не согласованная продуктовая политика. ASSISTANT_MAX_CONCURRENT (1–20, технический default 5) относится только к мастерской. Для диагностики лимиты не менялись.

6 запросов/мин на аккаунт, одна активная операция на аккаунт, общая lease на 60 сек; AI deadline 35 сек, одна попытка, до 900 output tokens. Превышение → 429, без скрытой очереди. Дневное окно сбрасывается в 00:00 UTC; после допуска к обработке считаются также OOD/уточнения/ошибки провайдера. Повтор уже сохранённого ответа бесплатен. Эти правила требуют продуктового согласования. Повтор после 502 — новая попытка и расход квоты; ответ AI не был сохранён.

Очистку `ASSISTANT_RETENTION_DAYS=N npm run assistant:cleanup -- --apply` должен запускать планировщик оператора; без --apply только подсчёт. До настройки расписания мастерскую не включать. Ограничение контекста не заменяет удаление истории.

## Отзывы

`POST /api/feedback`: существующие X-Session-ID и HttpOnly proof cookie, без обязательной регистрации. Все четыре оценки обязательны:

```json
{"request_id":"<UUID>","route_id":null,"clarity":4,"recommendations":5,"navigation":4,"usefulness":5,"comment":"Понятно, куда идти дальше"}
```

Шкала целых 1–5, comment до 2000 символов, route_id только своей сессии. 10 попыток/час на сессию. 201 сохранён; повтор request_id — 200, новая строка не создаётся. Для изменённого отзыва использовать новый ID. Форма должна просить не указывать ФИО/телефон/email.

Выгрузка оператором: `npm run feedback:export -- /private/path/feedback.json`. Путь должен быть новым; файл 0600, без идентификатора сессии/почты. Никакого открытого GET всех отзывов.

## PDF маршрута

`GET /api/route/export/pdf?route_id=UUID`: аккаунт владельца; 5/мин; 200 application/pdf, private/no-store. ID маршрута возвращает GET/PUT /api/education-route в поле route_id. Результат содержит текущую сохранённую версию маршрута, класс/муниципалитет, профессию, завершённые этапы, выбранные возможности и ссылки. Данных новой LLM-генерации нет. Скрытые диагностические ответы/непривязанная последняя рекомендация не подмешиваются.

Состав полного отчёта SA-05 ещё не согласован. Сначала нужна явная связь route → recommendation snapshot, затем безопасное включение гипотез и обоснований. Экспорт текущего маршрута не является полным диагностическим отчётом.
