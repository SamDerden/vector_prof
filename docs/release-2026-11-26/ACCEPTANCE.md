# Состояния, приёмка, пилот и защита

## PM-02: функциональный прототип состояний для UI

| Вход / экран | Состояния и действия | Сохранение / восстановление |
|---|---|---|
| Демо | Профиль → уточнения → анализ → результат. Явная отметка демо | Демо отдельно от личной диагностики; refresh не создаёт новую генерацию |
| Анкета | Класс/трек → вопросы → уточнения → анализ; ошибки рядом с полями | Один session_id, доказательство владения; повтор операции с прежним request_id |
| Импорт PDF | Выбор → загрузка → обработка → уточнения → результат; неверный файл/скан/нехватка данных | Не обещать OCR и импорт непроверенных форматов. Сохранить введённое, предложить анкету при неподдерживаемом файле |
| Мастерская | Гостю предложение войти; далее профессия, пять согласованных стартовых вопросов, ввод, ожидание, ответ и источники | Новый контекст при смене профессии; история аккаунта; при 429 показать ожидание/повтор, при 502 — повтор без потери текста |
| PDF | Сохранить маршрут → скачать; загрузка/успех/нет доступа/ошибка | Скачивается сохранённая версия; не запускать AI |
| Отзывы | Четыре оценки, необязательный комментарий, отправка/ошибка/спасибо | При потере ответа повторять request_id, не дублировать запись |

Это спецификация состояний, не утверждённый визуальный макет. Макеты трёх новых сценариев зависят от SA-01–05.

## PM-03/07: протокол пилота

До пилота: подтвердить дату, классы, устройства, сеть, ответственного взрослого и разрешённый сбор данных. Синтетические проверки до школьников. Участникам не объяснять, какую профессию «должен» дать результат.

Задание: пройти диагностику; объяснить своими словами результат; выбрать возможности хотя бы из двух гипотез; сохранить маршрут; вернуться после обновления; скачать маршрут; задать два вопроса мастерской (только если допущена); оставить четыре оценки и комментарий. PDF-импорт — отдельная группа с реальными обезличенными файлами, если сценарий принят.

Таблица наблюдения: anonymous participant_code, grade_group, device, scenario, started_at, completed_at, recommendation_received, route_saved, pdf_success, assistant_success, error_code, assistance_needed, comment. Без ФИО/email. Отдельно фиксировать отказ/пропуск, а не превращать его в успех.

Предлагаемые цели плана (ещё не утверждены): завершение ≥90%; получение рекомендаций ≥95%; самостоятельный маршрут ≥85%; средние оценки ≥4/5; импорт/экспорт ≥95% соответствующих попыток; критических ошибок 0.

Отчёт: для каждой метрики числитель/знаменатель и процент; отдельно по сценарию, устройству и классу. Время p50/p95, причины незавершения, доля помощи, перечень дефектов с частотой. Не делать выводы о точности профориентации по одной оценке удовлетворённости.

## PM-08: обработка дефектов

P0: раскрытие данных, потеря/смешение ответов, недоступность ключевого пути, неограниченный расход. Остановить затронутую функцию; owner, воспроизведение, исправление, regression.
P1: существенное затруднение с обходным путём; исправить до финальной защиты.
P2: косметика; приоритет по частоте. У каждого дефекта commit исправления и результат повторной проверки. Отдельно фиксировать известные ограничения.

## PM-09: сценарий защиты, 7–10 минут

1. Проблема и аудитория (1 мин): инструмент исследования интересов, не обещание единственной профессии.
2. Диагностика и прозрачный результат (2 мин): демо-профиль, реальные сохранённые ответы, гипотезы и объяснения.
3. Маршрут (2 мин): выбор возможностей разных профессий, сохранение и возврат, PDF.
4. AI-мастерская (1–2 мин, только принятая): контекст профессии, источник, честный ответ при нехватке данных.
5. Проверки и пилот (1 мин): только фактические показатели; отдельно mock и live, lexical и semantic.
6. Ограничения/дальнейшие шаги (1 мин).

Резерв: заранее проверенный сохранённый результат и локальный PDF; при отказе AI показать сохранённый пример с явной подписью. Не выдавать резерв за новый live-ответ. Финальная репетиция 14.12, фактические результаты добавить после пилота.
