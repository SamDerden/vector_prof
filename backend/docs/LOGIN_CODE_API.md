# Вход по одноразовому коду

Парольный `POST /api/auth/login` не меняется. Код входа — отдельная пара запросов. Оба ответа не сообщают, есть ли такой email.

## POST /api/auth/login/code

Тело: `{ "email": "student@example.test" }`.

- Неверный формат email: `400 { "error": "validation" }`.
- Любой корректный email, в том числе неизвестный, неактивный и уже подтверждённый: `202 { "status": "accepted" }`.
- Письмо уходит только активному аккаунту, через тот же SMTP-транспорт. Тема: «Код для входа».
- Лимит: одно письмо в 60 секунд и не больше пяти за час на адрес. Иначе `429 { "error": "rate_limited" }`.
- В JSON, cookie и логах кода нет.

## POST /api/auth/login/code/verify

Тело: `{ "email": "student@example.test", "code": "123456" }`.

- Верный действующий код: `200` и пользовательская сессия. Cookie `vector_auth_session` — HttpOnly, как при входе по паролю.
- Неизвестный адрес, чужой код, неверный код, просроченный код, исчерпанные попытки и повтор уже использованного кода: один и тот же ответ `400 { "error": "invalid_code" }`. Сессия не создаётся.
- Срок кода — 15 минут. Неверных попыток — пять, затем код больше не принимается.
- Новый код для того же адреса и назначения `login` сразу гасит все предыдущие действующие коды. После успешного кода B код A больше не принимается.
- Подтверждение забирает код условным `UPDATE ... WHERE consumed_at IS NULL` в той же транзакции, где создаётся сессия. Параллельные подтверждения одного кода открывают не больше одной сессии и не ставят cookie при отказе.

Повторная отправка регистрации и сброс пароля гасят предыдущие коды того же назначения так же: в одной транзакции PostgreSQL под advisory-lock.
